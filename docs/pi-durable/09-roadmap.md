## Prototype 1 — Durable Delivery boundary (resolved at an option-2 contract)

Durable delivery identity for routine notes is opt-in (`FM_PI_DURABLE_DELIVERY`): a routine note stores its own delivery record keyed by store `seq`, so a reload finds it and delivers nothing again; a sequence match with different content fails closed; the default path is unchanged.

**Status: loss/duplicate safety structural; option-2 stale-delivery relaxation.** The destructive stale-owner cleanup is removed (no code path deletes a durable record a replacement is adopting). Both **creation** and **reclaim** are fenced by exclusive-create (`linkSync`): creation via the marker, reclaim via a per-sequence `<seq>.claim` whose link *is* the publish, so no takeover can interleave. Verified across the doc-26 counterfactual and adversarial claim attacks — exactly one durable home-wide record and one visible delivery, no reachable duplicate or loss. The recorded **option-2 contract** still permits an already-authorized in-flight delivery to finish and be adopted after takeover, so the "a superseded owner cannot deliver" invariant is **not** met. Residuals: free-running multi-process reclaim untested; an externally corrupted `.claim` stalls a row (liveness-only, unreachable via the extension's own writes); a live-but-replaced owner stalls its row until it exits; a committed reservation whose record lives only in a different destination defers there. See [`27-reclaim-claim.md`](27-reclaim-claim.md) / [`28-reclaim-claim-verify.md`](28-reclaim-claim-verify.md).

Documented residuals (unchanged): free-running multi-process races untested; a committed reservation whose recorded-destination record is externally destroyed strands; legacy bare/empty markers inherit that strand.

## Prototype 0 — Durable Outcome persistence (complete)

Proven claim: durable execution prevents duplicate outcome **appends** caused by replay/retry (the replayed append commits exactly one row per logical note). The symmetric F09 lane also established the negative: durable execution does **not** prevent duplicate externally visible routine-note **delivery**, because routine presentation occurs downstream in a shared, non-idempotent consumer.

Evidence: `docs/pi-durable/06-evaluation-report.md`; verifications `08-benefit-verification.md` and `10-benefit-verification-2.md`; the symmetric lane in `06` (existing 30/30 vs durable 30/30 duplicate deliveries, one stored row on durable replay).

## Spike 1 — make real-path F09 reproducible (completed)

Before changing any contract, reproduce the exact sequence through the **real Pi extension**:

```
routine note delivered -> cursor write fails -> note stays unread -> re-present on retry
```

If this cannot be driven headlessly, **stop and document why** rather than building around another reduced model. This retires the real-Pi-fidelity residual risk and is the precondition for Prototype 1.

## Prototype 1 — Durable Delivery boundary (promotion criterion — met)

Introduce **durable delivery identity** — something like `(outcomeSeq, destination/presentation target)` with a durable state transition — so the system knows a particular external delivery already happened independently of whether the read cursor advanced. Keep the proven append durability unchanged.

Re-run the exact symmetric F09 experiment. Promotion criterion:

- existing path: duplicate delivery under the injected fault;
- new durable-delivery path: exactly one externally visible delivery;
- no lost delivery; no stale-owner delivery;
- replay/restart/takeover preserve those invariants.

Then adversarially attack the new boundary: delivery started -> crash; delivery succeeds -> ack persistence fails; concurrent consumers; takeover; partial ledger recovery; ack-owner change.

## Phase 1 — bounded, opt-in pilot (approved)

The captain promoted Prototype 1 to a **bounded, opt-in Phase 1 pilot under option 2** on 2026-10-05, with the documented residuals accepted. Consolidates the former `pi-durable-phase1-final` / `pi-durable-phase1-contract` / `pi-durable-phase1-promotion` holds into one promotion decision.

- Delivery stays opt-in (`FM_PI_DURABLE_DELIVERY`); the default flag-off path is unchanged.
- **Option 2 stands:** an already-authorized in-flight delivery may finish and be adopted after takeover; the "superseded owner cannot deliver" invariant is **not** met.
- The no-loss/no-duplicate claim is scoped to the verified schedules (the lab-interleaved F09 schedules in `28`), not to free-running multi-process reclaim.
- Phase 1 must validate, before broader adoption: **real lock handover**, **normal session lifecycle**, and a **concurrent soak**.

The former gate text: advance only when the real Pi path demonstrates that a committed routine note is externally delivered **at most once** across the documented F09 failure window, while preserving at-least-once recovery and authority correctness. ("At most once" alone can be achieved by dropping messages; the target is exactly-once observable behavior for this delivery path, built from durable identity and recovery semantics.) The bounded pilot measures this on the real path; broader adoption follows only on its evidence.

**Pilot outcome (2026-10-05).** The bounded pilot (`29`) and its independent verification (`30`) confirm the runtime result on the real path: the extension's real `ps`-walked ancestry owns the lock (not a depth-0 self-pid), an in-flight handover under option 2 yields one visible delivery with no loss, and a 60-cycle concurrent soak shows **0 duplicates / 0 losses**; the flag-off body is byte-identical to the pre-Phase-1 extension (`8d9343…`). The harness gate defect found by `30` (the byte-for-byte baseline gate swallowed by a `try/catch`) was fixed and re-verified in `31`: a mutated baseline now fails the run and names the mismatch, the shipped negative control is non-vacuous, the soak counts raw durable entries, and an unloadable baseline is fatal rather than a passing residual. The lock/delivery logic was unchanged throughout.

**Live-session pilot (2026-10-06).** A single live session (`32`) ran in a disposable `$TMPDIR` home with the real `pi` 1.0.4 binary and a real model turn: routine delivery produced one durable record and one visible delivery; restart did not re-deliver an acknowledged note while it re-presented an unread one exactly once; an option-2 lock handover had the successor adopt the committed record and the replaced live owner finish without appending, for one home-wide delivery and no loss; and the flag-off rollback reconciled a pending delivery before switching, with an unreconciled negative control that reproduces the duplicate. Independent verification (`33`) returned **ADVANCE** — the live path is genuinely live (real binary, model, and ancestry walk), no duplicate or loss was producible, and the "not driven" limits are accurate. **Not yet driven:** the watcher extension, the branch session, wake dispatch, and a full attended fleet; the live guard also asserts only the `pi` exit code, not response content. Broader adoption waits on that.

**Attended-fleet pilot (2026-10-07).** The full-flow attended pilot (`34`) ran one opt-in disposable-lab session with `--durable-delivery` and the pinned revisions. Its durable-store path is sound: nine rows (seq 1-9), cursor 9, one delivery record per row, correct option-2 adoption of the in-flight seq 7 record, and a negative control that reproduces the duplicate when reconciliation is skipped. Independent review (`35`) nonetheless returned **HOLD - EVIDENCE**, not a clean pass: real user-visible presentation is unproven (seq 6 exists only as a `caveman_retrieve` tool result; seq 7 and seq 8 were never captured on a pane; seq 8 also wrote a persisted entry to the destination session while a fresh session advanced the cursor via a `display:false` nudge, so which writer advanced the cursor is unresolved); and watcher continuity is unproven (three non-owner-refusal alarms, not one; the opt-in extension log was off; the cycle-exit log shows no-watcher gaps with `successor=none` and a pending-downtime tail). The trial is **not** marked clean. A rerun must preserve the in-flight handover overlap, enable watcher diagnostics, and define the expected non-owner-refusal classification before running. Captain decision held as `pi-durable-attended-pilot-gate-decision`.

**Corrected rerun (2026-10-07).** The captain chose (a): one corrected, bounded rerun with the overlapping handover and frozen criteria (watcher diagnostics and timeline; per-sequence persistence/presentation/acknowledgement; cursor attribution; stop at the first gate failure). The restart/startup-replay case ran first and **failed the gate**: a **non-silent** row (seq 4) was consumed by `bin/fm-session-start.sh` -> `fm-branch-outcome.sh startup-replay`, which advanced the cursor 3 -> 4 and printed the row only into the session-start digest (retrieved as a `caveman_retrieve` **tool result**), with **no rendered `display:true` entry and no on-screen line**. seq 1-2 were visibly rendered and seq 3 was correctly suppressed, so the durable presentation path itself was not shown defective; the defect is that **startup replay consumes an unread non-silent row before any wake dispatch can present it**. The trial stopped there; the overlapping handover and rollback were **not** exercised. Watcher continuity held in normal operation with **no failure alarm** (the earlier three refusals did not recur with diagnostics on and a clean lab root); the restart produced a measured **coverage gap** (watcher down ~315 s until the resumed session's first turn), and queued-wake recovery across it was clean. See [`36-attended-pilot-rerun.md`](36-attended-pilot-rerun.md); independent review to follow.

Independent review (`37`) re-derived the findings from the raw artifacts and **confirmed the gate failure**, with a sharper diagnosis: the durable presentation path is **not defective in isolation** (it rendered seq 1-2 and correctly suppressed seq 3); the defect is an **interaction** — `bin/fm-branch-outcome.sh` documents the cursor as the highest seq "presented", but `startup-replay` advances it for leading non-silent routine rows on the strength of the printed digest alone, which under durable delivery is only a tool result. Two writers own one cursor with different notions of "presented". Verdict **HOLD - IMPLEMENTATION**. Preferred fix: make `startup-replay` durable-delivery-aware (do not advance the cursor past leading non-silent routine rows when the durable path is in use; let `reconcileUnreadOutcomes` render and mark read; silent rows stay consumed), with a regression test distinguishing the durable and non-durable modes. The review also notes "startup replay always wins" is a race, not an absolute (a leading captain row is barred from the replay set).

**Cursor fix (2026-10-07).** `bin/fm-branch-outcome.sh startup-replay` is now durable-delivery-aware (`38`): with `FM_PI_DURABLE_DELIVERY` truthy it advances the cursor only through leading **silent** rows, leaving leading **non-silent** routine rows unread for the extension's `reconcileUnreadOutcomes` to render and mark read; without the signal the digest remains the presentation and behavior is unchanged. Independent adversarial verification (`39`) returned **ADVANCE** across six cursor-logic cases, the signal matrix (17 values), and byte-identical non-durable behavior, reproducing the failing-first. Documented residual: if the flag is set but the branch extension never activates, a leading non-silent row stays unread indefinitely (not lost — the digest still prints it — but not a qualifying rendered presentation); strictly better than pre-fix, and inherent to durable delivery. The remaining unexercised pilot work is the **overlapping handover and rollback** stages.

**Handover + rollback run (2026-10-08).** A bounded attended run (`40`) on the full pins (pilot `548fe337…`, helper `79477b92…`) passed all three gates. **Stage A** — a non-silent row appended with no owner running was presented on the resumed session by the **extension's `reconcileUnreadOutcomes`** (rendered entry + captured `⛵` pane line; cursor `2 -> 3` extension-attributed, startup-replay printed but did not consume), proving the `38` fix in the live path. **Stage B** — the overlapping option-2 handover: a second live primary reopened the recorded destination, **adopted** the committed record (store unchanged, exactly one home-wide delivery), and the released owner **started no new delivery**; no duplicate or loss. **Stage C** — the reconciled rollback did not replay delivered rows, a new row used the ordinary flag-off path, and the **separate disposable lane** unreconciled control reproduced the duplicate. Per-process readiness was checked on every resumed/successor process. Independent review (`41`) confirmed the three gates from the raw artifacts and found **no implementation defect**, but returned **HOLD - EVIDENCE** on the watcher section: a **non-owner refusal was surfaced** by the released owner when it lost the lock (expected under the lost-lock contract, and the successor's continuity was separately confirmed), which the report had mis-stated as "no alarm", and §2's per-process environment values lack a raw `/proc/<pid>/environ` capture. The report is corrected accordingly. Not exercised: the `reserved`-with-no-committed-record sub-state, a fresh (deferring) destination, a forced captain-verdict row, and any soak. Broader adoption remains pending.

A narrow **read-only re-verification** (`42`) of the corrected `40` confirmed all five correction points against the raw artifacts: the non-owner refusal meets the predefined exception because successor coverage was demonstrated (`restore 1515119 -> 1516033`, `confirmed`); the corrected §7 timeline and gap-marker citation (`pending/acked:handling:1466909…`) match the snapshots; §2's environment values are labelled launcher-set/behaviorally corroborated with the missing `/proc/<pid>/environ` captures retained as an evidence limitation; the verdict separates the confirmed gates from those limitations; and the "not exercised" list is scoped to this attended run (earlier harness work — reservation crashes, fresh-destination deferral, soak — remains valid but does not establish attended-fleet coverage). The reviewer's **explicit conclusion**: the environment-provenance gap is real but does **not** block the trial — the three delivery gates re-derive from artifacts that do not depend on those environment values — so the verdict is **ADVANCE**. Broader adoption is now the captain's decision.
